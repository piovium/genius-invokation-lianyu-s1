# 恋雨杯-S1 赛事服务改造需求文档

## 项目背景

恋雨杯-S1 是基于 Piovium 模拟器，通过利用模拟器现有设施，以各卡牌“巅峰”版本混战的方式的非官方性质七圣召唤比赛。

## 已有设施

- 原始项目（`upstream`）已通过相关改造，实现对局时选择版本、引入自定义卡牌，并在前端各组件中显示的功能。
- 现有分叉分支中，相关版本、自定义卡牌以外部配置方式（`https://piovium.github.io/lianyu-s1-data-config/config.json`）引入服务器，配置对局版本和设置，且完成了给前端各组件显示的传递链路。此外，后端侧禁用了版本选择相关功能。
- 本赛事服务器使用新数据库，设计完成后，**可直接删除 Migrations、重写数据库表 Schema 后发布**。

## 用户故事

### 用户角色

1. 游客。任意浏览器用户。
2. 注册用户。通过 QQ 作为唯一标识符，密码或通行秘钥（Passkey）作为认证方式的正式用户。
  1. 注册用户可通过 *报名* 成为参赛选手。
3. 若干管理员用户。

### CG1 游客：进行对局

和现有保持一致。唯有如下改动：

游客参与任何对局时，系统也在对局结束的入库，需记录牌组 JSON 信息（供统计面板用）。

所有实际开始的对局在结束入库时需同时记录回合数；尚未实际开局而由管理员关闭的对局回合数为空。

### CU1 用户：注册

移除 GitHub 登录功能。提供注册表单，用户需提供：
- QQ 号（字符串，唯一，不可修改，仅当 [API](./qq_group.md) 返回列表包含该 QQ 时开放后续 field 填入）
- 注册码（基于 HMAC 的时效令牌，根据秘钥、QQ 号计算）
- 昵称（可从 API 预填入）
- 密码/确认密码 或 passkey
- checkbox1：同时报名参赛 default = *报名开始时间* <= now < *报名截止时间*
- checkbox2：我已知晓比赛需在模拟器进行 default = false

- QQ号、注册码、昵称可从 searchParams 传入
- 提交时，若没有勾选 2，则前端拦截并提示。
- 注册码 field 帮助处，弹出加群链接和二维码，提示用户在群内向 bot 发起私聊获取注册码。[详](./qq_group.md)
- 后端验证注册码和 QQ 群列表是否包含用户后，执行注册
- 注册成功后，若本地已有游客牌组，则自动上传。
- 若用户勾选报名，则执行 CU3 中步骤

用户头像显示为实时获取的 QQ 头像：https://q1.qlogo.cn/g?b=qq&nk=<QQ>&s=640

注册码算法需：
- 提供 Python 版本的生成算法供 bot 实现
- 提供 Node 版本的验证算法

### CU2 用户：登录

用户使用 QQ 号和密码或 passkey 登录。

### CU3 用户：报名

在创建房间上方的醒目位置，若用户没有报名比赛，则展示“报名参赛”按钮，点击报名时额外校验一次 QQ 号当前是否是赛事群的群成员。

报名无需用户提交额外表单。仅在 *报名开始时间*（含）至 *报名截止时间*（不含）之间可报名。已报名用户超过 *报名限额* 时，会提示用户“当前报名人数已满，您还可继续候补但不保证参赛”。

若用户已报名，则成为报名用户。报名用户可背 *管理员* 设定为 *参赛选手*。参赛选手存在以下额外功能：
- 我的比赛 section，包括所有该用户参与的、归属于 *活跃场次* 、未 *结束* 的 *比赛盘次*，按预计开始时间倒序，每盘包括如下信息：
  - 该盘次的对手昵称， *预计开始时间*、*预计结束时间* ；所属 *场次* 名称。
  - 该盘次下的所有对局，与现有主页房间类似但颜色有区分
  - 对于 *未开始* 和 *进行中* 的对局，可点击进入 *赛事对局房间* （见 CU5）。
- 用户不在 *进行中* 对局时可以取消报名（仅报名）或退赛（已成为参赛选手），成为普通用户。

### CU4 用户：牌组管理

若参赛选手现在处于 *收集牌组中* 的 *比赛场次*（参赛选手只能处于某一场次的单一 *盘次* 中），则存在以下额外功能：
- 在“我的牌组”页面，将某套牌组设置为比赛牌组，或取消设置。
- 设置比赛牌组必须校验该用户**没有相同三张角色牌的牌组**。如用户已有 A、B、C 三张角色牌构成的比赛牌组，则牌组包含角色 A、C、B（顺序不同）也不能添加为比赛牌组。
- 编辑比赛牌组不可以增删角色（但可以修改顺序），提示用户增删角色需新创建牌组。
- 比赛牌组和其他牌组分开显示，且通过卡片颜色区分。
- 若该场次限制牌组数量，且当前比赛牌组数量 大于等于 该场次的 *限制牌组数量* ，则不可以设置更多的比赛牌组。

若不满足 比赛场次阶段 要求，则不允许用户进行任何比赛牌组增删或编辑操作。

### CU5 用户：进入比赛

恋雨杯S1 对局分为三个层级管理：
- 手动创建的比赛场次；
- 每个场次下会有多个盘次；盘内对手固定；
- 每盘内存在半自动调度的比赛对局。

比赛场次包括如下内容：
- ID（自动生成）。
- 场次名称。
- 阶段（枚举）：收集牌组中、进行中、已结束；前二者称为活跃场次。
- 限制牌组数量：0 代表不限制

比赛盘次包括如下内容：
- ID（自动生成）
- 所属场次。
- 选手：1~2 位注册用户
- 预计开始时间：仅提示
- 预计结束时间：仅提示
- 每选手的比赛牌组 JSON（收集阶段完成后固化）
- 对局模式：无限制模式、*决斗模式*、*征服模式*
- 对局默认房间配置
- 总局数/胜局数：如 3局2胜（总局数 >= 胜局数 >= 1）
- 赢家选手ID：可空
- *是否自动创建新局*

其中，
- 决斗模式指：每局比赛后，双方使用的牌组将自动取消比赛牌组，无法继续使用。
- 征服模式指：每局比赛后，胜方使用的牌组将自动取消比赛牌组，无法继续使用；败者无限制。
- 盘次的“已完成”是指，赢家已设置 **或者** 总比赛局数（含无效对局） >= 设置的总局数。

比赛对局包括如下内容：
- 是否是比赛对局。若是，则关联盘次 ID
- 模拟器版本（commit hash）、对局版本（config version）
- 阶段（枚举）：未开始或进行中（仅在内存态区分）、已结束
- 结束原因（枚举）：正常结束、模拟器报错、玩家放弃对局、管理员介入
- 玩家0、玩家1 ID（游客对局可空）
- 玩家0、玩家1 牌组 ID（游客对局可空）
- 玩家0、玩家1 牌组 JSON（用于统计）
- 赢家：0 或 1 或 NULL（模拟器原始结果）
- *手动指定的赢家*（管理员介入后结果）
- 回合数（实际开局后结束时写入）
- 作为有效对局统计 default = true，模拟器报错时自动设置 false
- State Logs

参赛选手通过点击赛事对局卡片进入房间确认页面。该页面与已有加入房间弹窗基本一致，除牌组选择外其余字段不可改变。

若比赛所属盘次为无限制模式，则用户可从所有牌组中选择，否则只能从当前用户配置的比赛牌组中选择。牌组耗尽无法开始牌局的，不自动判负，由管理员介入处理。

### CU6 用户：编辑信息

用户可编辑自己的昵称，不可编辑自己的头像。

### CA1 管理员：登录

管理员使用特定 QQ 号和密码登录。

### CA2 管理员：参赛管理

- 可以以列表形式查看所有的注册用户，可以按照报名状态筛选、报名时间排序，批量选择和更改报名状态为参赛选手、取消报名或强制退赛。取消报名、强制退赛需确保用户不在对局中（可先通过 *管理员介入* 终止对局），操作需保留审计日志。
- 管理员可设置报名开始时间、报名截止时间和报名限额；开始时间必须早于截止时间。

### CA3 管理员：场次创建与编辑

管理员按场次发布比赛。

管理员创建场次，除指定名称、初始阶段、限制牌组数量外，还可批量在其中发布盘次，包括如下两部分：
- 盘次信息：对局数，胜场数（如3局2胜），预计开始时间，预计结束时间，房间设置，对局模式。
- 每盘选手。具体界面可按如下设计：
  - 上方为已选玩家，左右两个列表，分别为 *玩家0列表* 和 *玩家1列表*，每个列表各自有洗牌和倒序按钮，列表内的每个玩家都能单独被移除或修改顺序。
  - 下方为全部**参赛选手**列表，排除已位于活跃场次内的玩家。
    - 提供“根据选择的多个场次进行筛选排序”的功能，见[筛选排序说明](./round_based_filter_sort.md)。筛选后显示具体排序数据。
    - 提供多选、全选，一键加入玩家0列表或玩家1列表。已加入某方列表的玩家不可选中。
    - 每个玩家也可单独操作加入某侧列表。

批量发布盘次时，玩家0列表 和 玩家1列表 依序两两成对；末尾余下盘次成为 *轮空盘次*。两个玩家列表将，分别按盘次信息设置对应盘次。创建场次时应验证所有玩家都不在已有活跃场次中（否则提示应设置结束对应场次）。

- 场次一经创建后不可增删盘次。
- 管理员可步进场次阶段。
  - 当步进至 进行中 阶段时，其下所有设置了 自动创建新局 的盘次，在满足条件时会自动创建一局比赛（见 CA4）。
  - 无关乎其下盘次对局是否全部完成，管理员都可结束场次。场次结束后，自动清除双方的比赛牌组。
- 管理员可以 JSON 格式导出数据，包括：
  - 场次元信息
  - 每盘的盘次元信息，需包括该盘双方玩家当前的（收集阶段）/该盘的（收集完成后）比赛牌组列表
  - 每局的对局信息和结果（不含 State Log）

### CA4 管理员：管理盘次和比赛对局

管理员进入盘次管理界面后，显示其下的对局列表。
- 若该盘存在两位参赛选手，在所属场次阶段为 进行中，且没有其它 未开始或进行中 的对局时（保证全盘仅有一开放对局），可执行 *自动创建新局* 或 由管理员手动创建新局：新建对局状态为未开始；先后手随机分配后填入玩家 ID 至数据库。
- 若只有一位参赛选手（轮空或另一方退赛），则管理员可手动执行“自动胜利”标记该盘赢家。
- 否则（双方退赛），不可以新建对局。

双方玩家进入 未开始 的对局房间后（内存状态变为进行中），回填牌组 ID 和 JSON 至数据库。
游戏正常（或因一方放弃对局）结束后，进行以下操作（事务）：更新状态为 已结束，回填赢家和对局日志，随后
- 如果盘次的对局模式为决斗，将比赛双方使用的 牌组，及角色牌构筑完全相同的牌组 取消比赛牌组；
- 如果盘次的对局模式为征服，将赢家使用的 牌组，及角色牌构筑完全相同的牌组 取消比赛牌组。
- 若当前盘次允许 自动创建新局，则检查对局所属的盘次信息和对局记录；若未达盘次胜局要求且已结束的局数未达到总局数，则自动在当前盘次创建一个新的比赛对局。
- 若盘次胜局要求已达成，则设置该盘次赢家。

该结束后操作与所有创建新局操作都应在数据库层面互斥。

每局比赛可被**管理员介入**，以处理异常或违规对局：对局赢家和状态、盘次赢家可以手动指定（若对局正在进行中，手动指定其它状态将立刻中止游戏结算）。管理员介入后立刻关闭该盘的自动创建新局，介入**不**导致自动恢复此盘禁用过的牌组，也**不会**对之前自动创建的对局进行额外终止操作。管理员介入需保留审计日志。

- 对局维持现状，**进行中不做持久化设计**（进行中对局服务端意外中断重启后，数据库内仍为未开始对局）。
- 对局可以被设置为不计入统计。

### CA5 管理员：查看对局 metrics 面板

metrics 面板包括所有对局（含比赛、房间、游客房间，需双方进行过对局，且计入统计）的信息：每张角色牌单卡、行动牌单卡、三角色组合的出场数/率（分母=2*对局数），胜场，胜率（按原始赢家不按手动指定者）；三角色组合的外战胜率。可根据数据源是否比赛对局筛选。

metrics 面板可查看所有注册用户的信息：胜场、胜率、所有使用过的牌组。可根据对局数据源是否比赛对局筛选。

> 注意：metrics 始终使用原始对局赢家（剔除不计入统计），场次筛选/小分计算按盘次赢家（由对局完成自动设置/管理员介入设置），两者不同。

### CA6 管理员：其它

- 管理员可 bypass 房间可见性设置和是否观战设置。
- 管理员可以直接指定某盘比赛某选手的比赛牌组，该操作需保留审计日志。
