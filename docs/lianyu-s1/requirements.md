# 恋雨杯-S1 赛事服务改造需求文档

## 项目背景

恋雨杯-S1 是基于 Piovium 模拟器，通过利用模拟器现有设施，以各卡牌“巅峰”版本混战的方式的非官方性质七圣召唤比赛。

## 已有设施

- 原始项目（`upstream`）已通过相关改造，实现对局时选择版本、引入自定义卡牌，并在前端各组件中显示的功能。
- 现有分叉分支中，相关版本、自定义卡牌以外部配置方式（`https://piovium.github.io/lianyu-s1-data-config/config.json`）引入服务器，配置对局版本和设置，且完成了给前端各组件显示的传递链路。此外，后端侧禁用了版本选择相关功能。
- 本赛事服务器使用新数据库，设计完成后，**可直接删除 Migrations、重写数据库表 Schema 后发布**。

## 用户故事

### 用户角色

1. 游客。任意浏览器用户。
2. 注册用户。通过 QQ 作为唯一标识符，密码或通行秘钥（Passkey）作为认证方式的正式用户。
  1. 注册用户可通过 *报名* 成为参赛选手。
3. 若干管理员用户。

### CG1 游客：进行对局

和现有保持一致。唯有如下改动：

游客参与任何对局时，系统也在对局结束的入库，需记录牌组 JSON 信息（供统计面板用）。

### CU1 用户：注册

移除 GitHub 登录功能。提供注册表单，用户需提供：
- QQ 号（字符串，唯一，不可修改，仅当 [API](./qq_group.md) 返回列表包含该 QQ 时开放后续 field 填入）
- 注册码（基于 HMAC 的时效令牌，根据秘钥、QQ 号计算）
- 昵称（可从 API 预填入）
- 密码/确认密码 或 passkey
- checkbox1：同时报名参赛 default = now < *报名截止时间*
- checkbox2：我已知晓比赛需在模拟器进行 default = false

- QQ号、注册码、昵称可从 searchParams 传入
- 提交时，若没有勾选 2，则前端拦截并提示。
- 注册码 field 帮助处，弹出加群链接和二维码，提示用户在群内向 bot 发起私聊获取注册码。[详](./qq_group.md)
- 后端验证注册码和 QQ 群列表是否包含用户后，执行注册
- 注册成功后，若本地已有游客牌组，则自动上传。
- 若用户勾选报名，则执行 CU3 中步骤

用户头像显示为实时获取的 QQ 头像：https://q1.qlogo.cn/g?b=qq&nk=<QQ>&s=640

注册码算法需：
- 提供 Python 版本的生成算法供 bot 实现
- 提供 Node 版本的验证算法

### CU2 用户：登录

用户使用 QQ 号和密码或 passkey 登录。

### CU3 用户：报名

在创建房间上方的醒目位置，若用户没有报名比赛，则展示“报名参赛”按钮，点击报名时额外校验一次 QQ 号当前是否是赛事群的群成员。

报名无需用户提交额外表单。*报名截止时间* 前才可报名。

若用户已报名，则成为报名用户，报名用户存在以下额外功能：
- 我的比赛 section，包括所有该用户参与的 *收集牌组中*、*进行中*、*已结束* 的 *比赛场次* ，包括如下信息：
  - 该场次的 *预计开始时间*、*预计结束时间* ；对手昵称；所属 *轮次* 名称。
  - 该场次下的所有对局，与现有主页房间类似但颜色有区分
  - 对于 *未开始* 和 *进行中* 的对局，可点击进入 *赛事对局房间* （见 CU5）。
- 用户不在活跃 *场次* 中时可以取消报名，成为普通用户。

### CU4 用户：牌组管理

若报名用户现在处于 *收集牌组中* 的比赛场次（报名用户只能处于单一场次中），则存在以下额外功能：
- 在“我的牌组”页面，将某套牌组设置为比赛牌组，或取消设置。
- 设置比赛牌组必须校验该用户**没有相同三张角色牌的牌组**。如用户已有 A、B、C 三张角色牌构成的比赛牌组，则牌组包含角色 A、C、B（顺序不同）也不能添加为比赛牌组。
- 编辑比赛牌组不可以增删角色（但可以修改顺序），提示用户增删角色需新创建牌组。
- 比赛牌组和其他牌组分开显示，且通过卡片颜色区分。
- 若该场次限制牌组数量，且当前比赛牌组数量 大于等于 该场次的 *限制牌组数量* ，则不可以设置更多的比赛牌组。

若不满足 比赛场次阶段 要求，则不允许用户进行任何比赛牌组增删或编辑操作。

### CU5 用户：进入比赛

恋雨杯S1 基于 手动调度的比赛场次 和每场次内多个 半自动调度的比赛对局 构成。

比赛场次包括如下内容：
- ID（自动生成）。
- 选手：2 位注册用户
- 阶段（枚举）：未开始、收集牌组中、进行中、已结束；中间二者称为活跃场次。
- 预计开始时间：仅提示
- 预计结束时间：仅提示
- 限制牌组数量：0 代表不限制
- 对局模式：无限制模式、*决斗模式*、*征服模式*
- 默认房间配置
- 总局数/胜局数：如 3局2胜（总局数 >= 胜局数 >= 1）
- *是否自动创建新局*

其中，
- 决斗模式指：每场比赛后，双方使用的牌组将自动取消比赛牌组，无法继续使用。
- 征服模式指：每场比赛后，胜方使用的牌组将自动取消比赛牌组，无法继续使用；败者无限制。

每场对局包括如下内容：
- 是否是比赛对局。若是，则关联场次 ID
- 模拟器版本（commit hash）、对局版本（config version）
- 阶段（枚举）：未开始或进行中（仅在内存态区分）、已结束
- 玩家0、玩家1 ID（游客对局可空）
- 玩家0、玩家1 牌组 ID（游客对局可空）
- 玩家0、玩家1 牌组 JSON（用于统计）
- 赢家：0 或 1 或 NULL（模拟器原始结果）
- *手动指定的赢家*（管理员介入后结果）
- 作为有效对局统计 default = true
- State Logs

报名用户通过点击赛事对局卡片进入房间确认页面。该页面与已有加入房间弹窗基本一致，除牌组选择外其余字段不可改变。

若比赛所属场次为无限制模式，则用户可从所有牌组中选择，否则只能从当前用户配置的比赛牌组中选择。牌组耗尽无法开始牌局的，不自动判负，由管理员介入处理。

### CU6 用户：编辑信息

用户可编辑自己的昵称，不可编辑自己的头像。

### CA1 管理员：登录

管理员使用特定 QQ 号和密码登录。

### CA2 管理员：参赛管理

- 可以以列表形式查看所有的注册用户，可以按照报名状态筛选、报名时间排序，批量选择和更改报名状态。取消报名需确保用户不在活跃场次中，操作需保留审计日志。
- 管理员可设置报名截止时间。

### CA3 管理员：发布比赛

管理员按 *轮* 发布比赛。
每轮包括如下信息：
- ID（自动生成）。
- 轮次名称，必填，管理员手动输入。
- 该轮下的场次。

管理员创建轮次时，除指定轮次名称外，还需批量设置该轮下除选手外的场次信息：对局数，胜场数（如3局2胜），创建时的阶段，设计开始时间，设计结束时间，房间设置，限制牌组数量，对局模式。

选手如下配置。
- 上方为已选玩家，左右两个列表，分别为 *玩家0列表* 和 *玩家1列表*，每个列表各自有洗牌和倒序按钮，列表内的每个玩家都能单独被移除或修改顺序。
- 下方为全部**报名用户**列表，排除已位于活跃场次内的玩家。
  - 提供“根据选择的多个轮次进行筛选排序”的功能，见[筛选排序说明](./round_based_filter_sort.md)。筛选后显示具体排序数据。
  - 提供多选、全选，一键加入玩家0列表或玩家1列表。已加入某方列表的玩家不可选中。
  - 每个玩家也可单独操作加入某侧列表。

发布时，校验 玩家0列表 和 玩家1列表 长度是否相等。两个玩家列表将依序成对，分别按场次信息设置对应场次。创建场次时应验证两玩家不在已有活跃场次中（否则提示应设置结束对应场次）。

### CA4 管理员：管理场次和比赛对局

- 场次阶段、基础信息可以修改。显示所属轮次，以及其下的对局列表。
- 若两位玩家都是报名用户，则：
  - 管理员可以在该场次下手动新建一场比赛，状态为未开始；先后手随机分配后填入玩家 ID 至数据库。
  - 若只有一位玩家是报名用户（即另一方取消报名（“退赛”）），则管理员可执行“自动胜利”以插入一条占位对局数据库行，记录该玩家是胜者。
  - 否则，不可以新建对局（本场次只能结束）。
- 进行中 的场次、未开始 的对局，双方玩家进入房间后（内存状态变为进行中），回填牌组 ID 和 JSON 至数据库。
- 游戏结束后，进行以下事务操作：更新状态为 已结束，回填赢家和对局日志，随后
  - 如果场次的对局模式为决斗，将比赛双方使用的 牌组，及角色牌构筑完全相同的牌组 取消比赛牌组；
  - 如果场次的对局模式为征服，将赢家使用的 牌组，及角色牌构筑完全相同的牌组 取消比赛牌组。
  - 若允许*自动创建新局*，则检查对局所属的场次信息和对局记录；若未达场次胜局要求且已结束的局数未达到总局数，则自动在当前场次创建一个新的比赛对局。
- **管理员介入**。对局赢家和状态可以手动指定（若对局正在进行中，手动指定其它状态将立刻中止游戏结算）。管理员介入后立刻关闭自动创建新局，介入**不**导致自动恢复牌组，也**不会**对之前自动创建的对局进行额外终止操作。管理员介入需保留审计日志。
- 场次不会自动结束，通过管理员手动修改状态实现（可以做成按钮）。场次结束后，自动取消双方的比赛牌组设置。

- 对局维持现状，**进行中不做持久化设计**（进行中对局服务端意外中断重启后，数据库内仍为未开始对局）。
- 对局可以被设置为不计入统计。

### CA5 管理员：查看对局 metrics 面板

metrics 面板包括所有对局（含比赛、房间、游客房间，需双方进行过对局，且计入统计）的信息：每张角色牌单卡、行动牌单卡、三角色组合的出场数/率（分母=对局数），胜场，胜率（按原始赢家不按手动指定者）；三角色组合的外战胜率。可根据数据源是否比赛对局筛选。

metrics 面板可查看所有注册用户的信息：胜场、胜率、所有使用过的牌组。可根据对局数据源是否比赛对局筛选。

### CA6 管理员：其它

- 管理员可 bypass 房间可见性设置和是否观战设置。
- 管理员可以直接指定报名用户的比赛牌组属性，该操作需保留审计日志。
